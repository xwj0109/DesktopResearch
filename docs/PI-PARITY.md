# Pi in the conversation pane

## Current design: the real Pi CLI (2026-09-24)

The conversation pane now runs **the installed `pi` CLI itself** in a PTY (`desktop/terminal.ts`, rendered by `src/workbench/PiTerminal.tsx` with xterm.js in the app theme). CLI parity is therefore inherent, not re-implemented: your `~/.pi` settings, every extension (including ones that draw their own terminal UI), keybindings, themes, `/tree` and `/resume` selectors, the external editor, `!` shell commands and image paste all behave exactly as in a terminal.

- **One PTY per window and stage**, started through your login shell (same `PATH` and environment as Terminal) with `NODE_NO_WARNINGS=1 PI_SKIP_VERSION_CHECK=1`, like the `pi` alias. Switching stages keeps each CLI running. Coming back repaints the screen with a one-column width nudge instead of replaying raw bytes. Closing the window stops that window's CLIs (SIGHUP, then SIGKILL after 2 s), and quitting stops all of them.
- **Linked to your CLI sessions.** Pi runs in the strategy folder (`<data root>/workspaces/strategies/<id>`) with Pi's normal session storage, a stable session id per stage (`--session-id`) and a readable name (`--name "<strategy> · <stage>"`). `pi -r` or `pi -c` in that folder in Terminal reaches the same conversations, and so does the pane. Pi creates the session file with the first message, and prints a one-line notice on a stage's very first launch.
- **Research tools.** The pane adds `-e server/pi-research-extension.mjs`, a thin MCP client of the backend registry (see [principles](PRINCIPLES.md)). It authenticates with an in-memory token issued per backend run (`/native/agent-tools`), separate from the opt-in external MCP access. Without that environment the extension does nothing. The tools URL carries the pane's stage (`?stage=literature`, …), so each stage's Pi gets that stage's guidance with the tools. Literature, for example, starts from `ideas_pursued`. In Research Development, each pursued idea has its own conversation (`research:<idea id>`, its own stable session id) running in the idea's workspace folder, and the tools URL adds `&idea=r:<id>` so the instructions name the idea.
- **Pane integration.** "Ask Pi" and the review tray paste into the running CLI as a bracketed paste. Dropping files pastes their shell-escaped paths, like Terminal. ⌘C copies a terminal selection, and Option acts as Meta, so Pi's Alt shortcuts work.
- **The bar above the CLI** (app UI only; nothing in Pi changes). From left to right:
  - **Status dot:** running, working (pulsing), handed off or stopped.
  - **Session and model:** the session name and the current model and thinking level, read from the session file.
  - **≡ Read:** switches to the reading view.
  - **/ ▾:** a menu of Pi's built-in commands. Picking one types it into Pi, so Pi's own selector opens. The menu also has **Copy folder path**. Extension and skill commands are listed by typing `/` in Pi itself.
  - **+ Attach:** pastes the chosen files' escaped paths.
  - **↗ Terminal:** stops the pane's Pi and opens Terminal.app on the same session through a temporary `.command` file, so there are never two writers. **Resume here** brings it back.
  - **↻:** restarts Pi.
- **Reading view.** A read-only render of the active branch of this stage's Pi session JSONL (`src/workbench/pi-session.ts`, polled every 1.5 s through `pi-research:terminal-transcript`). It shows messages, tool calls with their results, compaction and branch summaries, and model and thinking changes. Markdown renders with KaTeX maths (`$…$`, `\(…\)`, `$$…$$`, `\[…\]`) and GFM tables. Typing any key returns to the CLI and sends that key. The app never writes Pi sessions.
- **No matching Pi theme.** Pi selects a theme only through its settings (global, or `.pi/settings.json` in the folder), which would also change `pi` outside the app. The terminal colours follow the app palette, but Pi's own theme is left as you configured it.
- **Traffic is not journaled.** Keystrokes and output travel over dedicated IPC channels (`pi-research:terminal-*`), not the research request journal.
- **Pi's own tools act in the strategy folder.** Pi's built-in bash, edit and write tools work there. Its `INDEX.md` projections are regenerated by the app and are not authoritative.
- **Earlier conversations** held in the previous graphical pane's private storage (`.runtime/sessions/…`) aren't part of the new CLI sessions. Open them in the pane with Pi's `/import <path>` if needed.

The graphical conversation described below is kept only as a fallback, for windows whose desktop bridge has no terminal support (test fixtures, older builds).

# Graphical Pi compatibility (fallback)

The left pane remains a graphical conversation. Its runtime is the installed Pi SDK, currently verified against **0.84.1**. This document distinguishes implemented behavior from exact CLI parity. **Full CLI parity has not yet been reached.** Do not describe a command name appearing in the menu as proof that every related CLI interaction is supported.

## Implemented

- Automatic connection and a persistent active runtime while the workspace backend is open; canonical Pi sessions survive a reconnect. Explicit Stop is respected.
- Installed models, thinking levels, prompt templates, skills, project resources, built-in extensions and registered extension commands.
- Streaming replies, thinking, tool events, canonical history, extension dialogs, custom editor/widget/footer surfaces and ANSI terminal rendering.
- Enter sends when idle and steers while a turn runs. Alt+Enter queues a follow-up. Alt+Up retrieves pending messages; cancellation also retrieves pending messages. The SDK schedules delivery. Recovered text and images return to the composer without replacing newer draft text.
- Effective installed keybindings for submission, newline, prompt history, model selection/cycling, thinking, tool folding, copy, interruption, dequeue, session commands and editor actions. Empty key arrays disable defaults. Native graphical text selection, clipboard and IME continue to work.
- Editor word/line movement, deletion, kill/yank, yank cycling, undo and character jumps. Ctrl+G runs the configured external editor in an owned PTY inside a temporary terminal surface, returning the saved draft when the editor exits successfully. Cancel/shutdown terminate that PTY.
- `/new`, `/resume`, `/tree`, `/fork`, `/clone`, `/name`, `/session`, `/compact`, `/settings`, `/scoped-models`, `/export`, `/import`, `/login`, `/logout`, `/trust`, `/share`, `/changelog`, `/copy`, `/quit`, `/editor`, and `!`/`!!` shell execution. Session replacements use the managed binding barrier.
- Runtime settings for delivery mode, transport, retry, compaction, double-Escape action, image handling, skill commands and HTTP timeout.
- Installed autocomplete provider and extension wrappers supply path and argument completions alongside research-source suggestions. Suggestions are ephemeral reads, not durable research operations.

## Deliberate desktop adaptations

- Quit/empty-editor exit stops the conversation runtime; it does not close all research windows. Ctrl+C preserves selected-text copying.
- Research attachment cards remain graphical. Their content is represented by the existing portable message format.
- Session discovery is restricted to the current managed research conversation directory. Import creates a new managed identity instead of adopting another workspace's canonical writer.
- Runtime settings use the existing session overlay. Explicit provider authentication and project trust use the installed SDK's stores.
- Queue recovery is bounded to eight pending items and roughly 700 KB serialized content so an acknowledged recovery fits one transport frame. A rejected enqueue retains the draft.
- The external editor PTY is packaged for the supported macOS/Apple Silicon desktop target. Its configured executable and flags follow Pi's space-separated editor command convention.

## Remaining gaps to close

- Exact CLI session/tree/model selector interaction: hierarchical folding, all filters, ordering, cross-directory browsing, rename/delete shortcuts and per-selector key maps. Current graphical dialogs expose core operations but are not the CLI selectors.
- All CLI presentation settings, themes and full-screen/alternate-screen behavior. Terminal job-control suspend has no direct equivalent for the graphical pane.
- Full editor fidelity: visual wrapped-line navigation for remapped movement, identical word segmentation/undo grouping, clipboard shortcuts across platforms and all autocomplete trigger/Tab behaviors. Current remote completion is bounded to 400 characters on a single line; longer or multiline drafts retain local suggestions.
- Sixel/Kitty/iTerm image protocols and extensions writing directly to process stdout. ANSI component surfaces work; unsupported graphics still produce an explicit diagnostic.
- Extension shortcuts while another native operation is busy remain serialized by the conversation operation gate.
- Live-provider acceptance of steering/follow-up races, OAuth flows, compaction/branch summarization and shared exports. These were implemented but not exercised with user credentials, paid inference or actual publication in development checks.

## Verification

`npm run check` runs boundary checks, TypeScript, the test suite and production web build. `tests/runtime-parity.test.ts` covers queue recovery, custom bindings, managed replacements, PTY editing/cancellation, editor actions and completion request scoping. `scripts/installed-parity-proof.ts` exercises the actual installed SDK in an empty temporary agent directory with inference disabled. It checks the command catalogue, effective bindings, completions and session/name/new operations. Desktop staging also verifies an exact payload inventory, including the PTY glue and native helper.

Parity changes must preserve the architecture in [PRINCIPLES.md](PRINCIPLES.md): research operations belong in the workbench registry. Pi conversation controls belong in the runtime adapter; renderer widgets only project them.
